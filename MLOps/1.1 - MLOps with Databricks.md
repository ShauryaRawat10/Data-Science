## MLOps Components and Principles

#### MLOps Components
- MLOps is a set of practice that help bring machine learning models to production in a scalable and efficient way

```
ML Code:
- Data Collection
- Data Verification
- Feature Engineering
- Configuration
- Automation
- Testing and Debugging
- Resource management
- Model analysis
- Process management
- Metadata management
- Monitoring
- Service Infrastructure

Minimal Set of Tools for MLOps:
- Version Control: GitLab, GitHub, Azure DevOps
- CICD: GitHub Actions, Azure Pipelines, Jenkins
- Orchestration: Airflow, AWS Step Functions, Databricks Workflows
- Model Registry: MLflow, Comet ML
- Container Registry: ACR, ECR, Docker Hub
- Compute: Kubernetes jobs, Databricks Jobs
- Serving: Databricks serving, Sagemaker endpoints, kebernetes
- Monitoring: ELK stack, Prometheus, Grafana
- Data Version Control: DVC, Delta Tables

Other MLOPs components:
- Feature Store: Feast, Tecton, Databricks
- Labeling: Labelbox, Scale AI
- Experimental Tracking: MLflow, neptune.ai, Weights and Biases
- Responsible AI: Arthur, Guardrails AI, Fiddler AI
- Vector database: Pinecone, Weaviate, Qdrant
- LLM Evaluation: Langcheck, HoneyHive
- LLM Frameworks: Langchain, LlanaIndex, AdalFlow
- Model Hub: Hugging Face, Amazon Bedrock, Databricks
```

- Real business impact is involved if ML model predictions are unavailable or of bad quality
- The goal of MLOps is to manimize risk of things going wrong

Four MLOps Principle:
- Documentation
  - Business goals and key performance indicators
  - Data Defintion
  - ML system architecture
  - Choice of ML model
- Code Quality
  - Review processes
  - Code Quality checks
  - Unit and Integration tests
- Traceability and reproducibity
  - For any model run or deployment in any environment, look into:
    - Corresponding code and commits on Git
    - Infrastructure used for training and serving
    - ML model artifacts
    - What data was used to train the model
  - Reproducibility
    - Same model with same data and code can be generated
    - Rollback is easy
- Monitoring and alerting
  - Infrastructure health and costs
  - Application health, response time, and response code
  - Model evaluation and business metrics
  - Data and model drift
